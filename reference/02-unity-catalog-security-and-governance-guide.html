Folha 02: Guia de Governança e Segurança com Unity Catalog

Metastore Regional, 3-Level Namespace, Managed vs External Tables & Volumes, Privilégios Hierárquicos (DCL), Row Filters, Column Masks e Delta Sharing.

1. Arquitetura do Unity Catalog: Metastore Regional & 3-Level Namespace

O Unity Catalog é o mecanismo unificado de governança do Databricks Lakehouse. Principais premissas arquiteturais testadas no exame:

  • Um Metastore por Região: Um único Metastore do Unity Catalog atende a múltiplos workspaces na mesma região da nuvem.
  • Namespace de 3 Níveis (catalog.schema.table_or_volume): Elimina a dependência do catálogo legado hive_metastore e possibilita consultas cruzadas totalmente qualificadas:
-- Consulta totalmente qualificada (FQDN) no Unity Catalog:
SELECT 
    c.id_cliente,
    c.nome_cliente,
    v.valor_total
FROM prod_lakehouse.financeiro.clientes AS c
JOIN prod_lakehouse.vendas.pedidos AS v
  ON c.id_cliente = v.id_cliente
WHERE v.data_pedido >= '2025-01-01';

2. Managed Tables vs External Tables

Característica Managed Table (Tabela Gerenciada) External Table (Tabela Externa)
Localização dos Dados Armazenada no storage raiz padrão associado ao Schema ou Catalog Armazenada em um caminho explícito dentro de uma External Location no ADLS Gen2
Comportamento do DROP TABLE Exclui os Metadados E os arquivos físicos de dados Parquet Exclui APENAS os Metadados no Unity Catalog; os dados físicos no ADLS Gen2 permanecem intactos
Criação Típica SQL CREATE TABLE cat.sch.tbl (id INT, nome STRING); CREATE TABLE cat.sch.tbl (...) LOCATION 'abfss://...';
Uso Recomendado Tabelas internas padrão criadas e gerenciadas 100% pelo Databricks Dados compartilhados com outras ferramentas ou ingeridos externamente

3. Managed Volumes vs External Volumes

Volumes governam arquivos não tabulares (CSVs brutos, JSONs, logs, imagens, PDFs, arquivos de modelo MLflow) com controle de acesso RBAC:

  • Managed Volume: Os arquivos residem no storage padrão do Unity Catalog. Se o volume for excluído com DROP VOLUME, os arquivos são apagados.
  • External Volume: Aponta para um caminho em uma External Location. Se o volume for excluído, os arquivos no ADLS Gen2 continuam preservados.
  • Caminho POSIX Padronizado: Acessível em código PySpark/Python via caminho montado: /Volumes/catalogo/schema/nome_volume/arquivo.csv.

4. Storage Credentials & External Locations (Infraestrutura de Acesso)

-- 1. Criação da Storage Credential usando a Identidade Gerenciada do Azure (Access Connector):
CREATE STORAGE CREDENTIAL cred_managed_identity
WITH (
    AZURE_MANAGED_IDENTITY = (
        RESOURCE_ID = '/subscriptions/.../resourceGroups/.../providers/Microsoft.Databricks/accessConnectors/meu-conector'
    )
)
COMMENT 'Credencial oficial usando Managed Identity com permissão Storage Blob Data Contributor';

-- 2. Criação da External Location associando o container ADLS Gen2 à credencial:
CREATE EXTERNAL LOCATION loc_adls_raw
URL 'abfss://raw@datalakeprod.dfs.core.windows.net/'
WITH (STORAGE CREDENTIAL cred_managed_identity)
COMMENT 'Localização externa para dados brutos de ingestão';

5. Matriz de Concessão de Privilégios Hierárquicos (DCL)

No Unity Catalog, o acesso é hierárquico e explícito. Para que um usuário consiga ler uma tabela, ele necessita de privilégios cumulativos em toda a árvore:

Objeto Privilégio Essencial Comando SQL Oficial
Catalog USE CATALOG GRANT USE CATALOG ON CATALOG prod_lakehouse TO `analistas_bi`;
Schema USE SCHEMA, CREATE TABLE GRANT USE SCHEMA, CREATE TABLE ON SCHEMA prod_lakehouse.vendas TO `analistas_bi`;
Table / View SELECT, MODIFY GRANT SELECT ON TABLE prod_lakehouse.vendas.pedidos TO `analistas_bi`;
Volume READ VOLUME, WRITE VOLUME GRANT READ VOLUME ON VOLUME prod_lakehouse.vendas.raw_files TO `engenharia_dados`;

6. Row Filters e Column Masks Dinâmicas (Proteção Fina de Dados)

-- 1. Função de Filtro por Linha (Row Filter): Analistas do Brasil só veem clientes do Brasil
CREATE OR REPLACE FUNCTION prod_lakehouse.seguranca.filtro_pais_cliente(pais STRING)
RETURN IF(is_account_group_member('diretoria_global'), true, pais = 'Brasil');

ALTER TABLE prod_lakehouse.vendas.clientes
SET ROW FILTER prod_lakehouse.seguranca.filtro_pais_cliente ON (pais_residencia);

-- 2. Função de Mascaramento Dinâmico de Coluna (Column Mask): Ocultar CPF para não autorizados
CREATE OR REPLACE FUNCTION prod_lakehouse.seguranca.mascarar_cpf(cpf STRING)
RETURN IF(is_account_group_member('compliance_auditores'), cpf, CONCAT('***.***.', RIGHT(cpf, 2)));

ALTER TABLE prod_lakehouse.vendas.clientes
ALTER COLUMN cpf SET MASK prod_lakehouse.seguranca.mascarar_cpf;

7. Delta Sharing & Auditoria com System Tables

  • Delta Sharing: Primeiro protocolo aberto do mercado para compartilhamento seguro de tabelas ativas com destinatários dentro ou fora do Databricks (via REST API aberta, sem replicação física de dados).
  • System Tables:
    • system.access.audit: Rastreia eventos de auditoria (quem consultou qual tabela, quando e de onde).
    • system.billing.usage: Rastreia o consumo exato de DBUs por workspace, cluster, SKU e tags de faturamento.
    • system.lineage.table_lineage: Rastreia a árvore completa de dependência entre tabelas e colunas.

8. ⚠️ Pegadinhas Críticas do Exame DP-750 (Unity Catalog)

  • Falta de USE CATALOG / USE SCHEMA: Conceder apenas GRANT SELECT ON TABLE tbl TO grupo; NÃO funcionará se o grupo não possuir USE CATALOG no catálogo pai e USE SCHEMA no schema pai.
  • Perda de Dados com DROP TABLE: Se uma tabela for Managed, o DROP TABLE exclui permanentemente os dados do storage. Se a intenção for apenas remover o registro do catálogo mantendo os dados no ADLS Gen2, ela deve ser criada como External Table.
