Folha 06: Cheatsheet de Workflows, DABs (databricks.yml) & System Tables

Databricks Workflows, Task Values, Repair Runs, Databricks Asset Bundles (DABs), CI/CD com Entra ID e System Tables.

1. Databricks Workflows: Multi-Task DAGs & Task Values

O Databricks Workflows é o orquestrador nativo totalmente gerenciado do Lakehouse para pipelines multitarefas:

  • Tipos de Tarefas Heterogêneas: Pode combinar em um único DAG tarefas de Notebook, scripts Python, consultas SQL/Alerts, pipelines Delta Live Tables (DLT) e dbt.
  • Task Values (Passagem de Parâmetros entre Tarefas):
# Tarefa 1 (Upstream): Define uma variável de saída compartilhada
total_registros_processados = 452000
dbutils.jobs.taskValues.set(key="total_rows", value=total_registros_processados)

# Tarefa 2 (Downstream): Lê a variável gerada pela Tarefa 1
linhas_anteriores = dbutils.jobs.taskValues.get(taskKey="tarefa_ingestao_bronze", key="total_rows")
print(f"Processando {linhas_anteriores} linhas na camada Silver...")

2. Repair Run no Databricks Workflows (Eficiência Operacional)

Se um job multitarefa de 10 etapas falhar na etapa 7 devido a uma instabilidade passageira de rede:

  • O que NÃO fazer: Reiniciar o job inteiro do zero (recalculando as etapas 1 a 6 e gastando DBUs desnecessárias).
  • Padrão Ouro DP-750: Executar um Repair Run. O Databricks reexecuta exclusivamente a tarefa que falhou (etapa 7) e suas dependências downstream, preservando os resultados das etapas concluídas com sucesso.

3. Databricks Asset Bundles (DABs) & Estrutura do databricks.yml

DABs é a ferramenta oficial de Infraestrutura como Código (IaC) e automação de CI/CD para projetos Databricks:

bundle:
  name: dp750_lakehouse_prod

targets:
  dev:
    mode: development
    default: true
    workspace:
      host: https://adb-dev.azuredatabricks.net
  prod:
    mode: production
    workspace:
      host: https://adb-prod.azuredatabricks.net

resources:
  jobs:
    etl_pipeline_diario:
      name: "[PROD] Pipeline Medallion Diário"
      schedule:
        quartz_cron_expression: "0 0 3 * * ?"
        timezone_id: "America/Sao_Paulo"
      job_clusters:
        - job_cluster_key: job_cluster_finops
          new_cluster:
            spark_version: 15.4.x-photon-scala2.12
            node_type_id: Standard_D4ds_v5
            autoscale:
              min_workers: 1
              max_workers: 4
      tasks:
        - task_key: ingestao_bronze
          job_cluster_key: job_cluster_finops
          notebook_task:
            notebook_path: ../src/01_ingestao_bronze.py
        - task_key: transformacao_silver
          depends_on:
            - task_key: ingestao_bronze
          job_cluster_key: job_cluster_finops
          notebook_task:
            notebook_path: ../src/02_transformacao_silver.py

4. Comandos CLI Essenciais de Databricks Asset Bundles

# 1. Validar a sintaxe dos arquivos YAML e caminhos do bundle:
databricks bundle validate

# 2. Fazer o deploy dos recursos no ambiente de desenvolvimento:
databricks bundle deploy -t dev

# 3. Fazer o deploy em produção e disparar a execução imediata:
databricks bundle deploy -t prod
databricks bundle run -t prod etl_pipeline_diario

# 4. Destruir os recursos criados pelo bundle no target:
databricks bundle destroy -t dev

5. Consultas Analíticas em System Tables (FinOps & Auditoria)

-- 1. Relatório FinOps: Consumo de DBUs agrupado por Job e SKU nos últimos 30 dias:
SELECT 
    usage_date,
    sku_name,
    usage_metadata.job_id,
    SUM(usage_quantity) AS total_dbus_consumidos
FROM system.billing.usage
WHERE usage_date >= current_date() - INTERVAL 30 DAYS
GROUP BY 1, 2, 3
ORDER BY total_dbus_consumidos DESC;

-- 2. Auditoria de Segurança: Rastreamento de acessos e modificações de privilégios:
SELECT 
    event_time,
    user_identity.email,
    action_name,
    request_params.catalog_name,
    request_params.schema_name,
    request_params.securable_type
FROM system.access.audit
WHERE service_name = 'unityCatalog'
  AND action_name IN ('grantPermissions', 'revokePermissions')
ORDER BY event_time DESC
LIMIT 50;

6. ⚠️ Pegadinhas Críticas do Exame DP-750 (Workflows & CI/CD)

  • Autenticação em CI/CD: NUNCA use tokens de acesso pessoal (PATs) de desenvolvedores individuais em pipelines de CI/CD (Azure DevOps / GitHub Actions). O exame exige Microsoft Entra ID Service Principals com autenticação federada OIDC.
  • Falha Parcial em Workflows: Ao identificar falhas em pipelines de produção, lembre-se da opção Repair Run para evitar reprocessamento dispendioso.
