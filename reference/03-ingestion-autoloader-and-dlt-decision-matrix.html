Folha 03: Matriz de Decisão: Auto Loader vs COPY INTO vs DLT vs Lakeflow

Critérios de seleção para Ingestão Incremental, Auto Loader (cloudFiles), Schema Evolution, Rescued Data e Delta Live Tables.

1. Matriz Definitiva de Decisão de Ingestão do DP-750

Critério / Requisito Auto Loader (cloudFiles) COPY INTO (SQL) Delta Live Tables (DLT) Lakeflow Connect
Escala de Arquivos Milhões de arquivos contínuos Milhares a centenas de milhares Qualquer escala declarativa Bancos OLTP relacionais e SaaS
Suporte a Streaming SIM (Spark Structured Streaming) NÃO (Apenas Batch idempotente) SIM (Streaming Tables) Automático via pipelines DLT
Schema Drift & Evolution Automático com _rescued_data Exige schema estável pré-definido Nativo em Streaming Tables Schema mapping gerenciado
Modo de Detecção Directory Listing ou Event Grid Varredura de diretório (List API) Gerenciado pelo runtime DLT CDC direto na fonte
Custo e Complexidade Baixíssimo; ideal para cloud files Mínimo; simples comando SQL Gerenciado; inclui Data Quality Conectores nativos Databricks

2. Auto Loader: Directory Listing vs File Notification

  • Directory Listing Mode (Padrão): O Auto Loader lista recursivamente os arquivos no diretório do storage no ADLS Gen2. É rápido e não exige nenhuma infraestrutura adicional no Azure. É recomendado para diretórios com até alguns milhões de arquivos.
  • File Notification Mode: Para diretórios que acumulam dezenas de milhões de arquivos, o Auto Loader cria automaticamente um Azure Event Grid e uma fila Azure Queue Storage para escutar notificações de novos blobs. Isso elimina a latência de listar arquivos e evita gargalos no Driver.

3. Schema Evolution Modes & Coluna _rescued_data no Auto Loader

-- Opções para cloudFiles.schemaEvolutionMode:
1. addNewColumns (Padrão): Novas colunas detectadas nos arquivos são adicionadas automaticamente ao schema Delta.
2. rescue: O schema permanece estrito, mas qualquer coluna nova ou dado corrompido é gravado na coluna _rescued_data.
3. failOnNewColumns: O pipeline falha imediatamente se detectar um campo novo, exigindo intervenção manual.
4. none: Ignora novos campos nos arquivos sem adicioná-los.

4. Snippet Padrão Ouro de Auto Loader com Trigger AvailableNow

from pyspark.sql.functions import current_timestamp

# Ingestão contínua com suporte a schema drift e processamento efêmero
df_stream = (spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "json")
    .option("cloudFiles.schemaLocation", "abfss://checkpoints@adls.dfs.core.windows.net/schemas/pedidos")
    .option("cloudFiles.schemaEvolutionMode", "addNewColumns")
    .option("cloudFiles.inferColumnTypes", "true")
    .load("abfss://raw@adls.dfs.core.windows.net/landing/pedidos/"))

# Adicionando metadados de ingestão
df_bronze = df_stream.withColumn("ingestion_time", current_timestamp())

# Gravando na camada Bronze com trigger AvailableNow (ideal para Job Clusters)
query = (df_bronze.writeStream
    .format("delta")
    .outputMode("append")
    .option("checkpointLocation", "abfss://checkpoints@adls.dfs.core.windows.net/checkpoints/pedidos_bronze")
    .trigger(availableNow=True)
    .toTable("prod_lakehouse.bronze.pedidos_raw"))

query.awaitTermination()

5. Comando COPY INTO (Batch SQL Idempotente)

-- Ingestão batch de arquivos Parquet com idempotência nativa:
COPY INTO prod_lakehouse.bronze.telemetria_copy
FROM 'abfss://raw@adls.dfs.core.windows.net/telemetria/'
FILEFORMAT = PARQUET
FILES = ('telemetria_20250101.parquet', 'telemetria_20250102.parquet')
FORMAT_OPTIONS ('mergeSchema' = 'true')
COPY_OPTIONS ('force' = 'false'); -- force=false garante que arquivos já carregados sejam ignorados

6. ⚠️ Pegadinhas Críticas do Exame DP-750 (Ingestão)

  • COPY INTO vs Auto Loader em Streaming: Se o enunciado mencionar carregamento contínuo ou streaming com schema drift inesperado, a resposta correta é Auto Loader (cloudFiles). COPY INTO só roda em batch estático.
  • Trigger Once vs AvailableNow: O trigger once=True está depreciado no Spark moderno. O padrão oficial testado no DP-750 para processar lotes pendentes em Jobs efêmeros é trigger(availableNow=True).
  • Onde os dados corrompidos vão no Auto Loader? Sempre para a coluna oculta especial _rescued_data em formato de string JSON.
