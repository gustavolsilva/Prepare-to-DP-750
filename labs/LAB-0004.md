# Lab 0004: Segurança de Rede (VNet Injection) e Sincronização Microsoft Entra ID (SCIM)

> **⚠️ PRÉ-REQUISITO OBRIGATÓRIO DA AZURE (Microsoft Learn Standards):**
> Para realizar este laboratório prático, **você precisará de um Workspace do Azure Databricks alocado na sua assinatura do Microsoft Azure** (Recomendado tier Premium para suporte a Unity Catalog e Serverless Compute).
> **Pré-requisitos Técnicos:** Assinatura Azure com permissão para criar Virtual Networks e Azure Databricks com VNet Injection.

- **Duração Estimada:** 40 minutos
- **Cenário:** A equipe de segurança da informação exige que todo o ambiente Databricks opere dentro de uma VNet corporativa isolada com duas subnets dedicadas /26 e que os acessos sejam sincronizados automaticamente a partir do Microsoft Entra ID via conector SCIM.

---

## Tarefa 1: Validar Requisitos de VNet Injection no Azure Portal

1. No portal do Azure, acesse 'Virtual Networks' e localize a VNet do Databricks.
2. Verifique as duas subnets obrigatórias:
   - Subnet 1 (Public/Host): Mínimo /26 (ex: 10.0.1.0/24), delegada para 'Microsoft.Databricks/workspaces'.
   - Subnet 2 (Private/Container): Mínimo /26 (ex: 10.0.2.0/24), delegada para 'Microsoft.Databricks/workspaces'.
3. Verifique o Network Security Group (NSG) associado para garantir que não haja regras de bloqueio de saída na porta 443 nem entre subnets para tráfego de shuffle interno.

---

## Tarefa 2: Inspecionar o Databricks Account Console para Sincronização SCIM

1. Acesse o console corporativo do Databricks em `https://accounts.azuredatabricks.net`.
2. No menu lateral, clique em 'User Management'.
3. Observe a lista de usuários e grupos sincronizados a partir do Microsoft Entra ID.
4. Verifique a existência de grupos corporativos (ex: `dp750_data_engineers`, `dp750_bi_analysts`). No exame DP-750, a governança moderna proíbe a criação de usuários manuais em cada workspace individual; tudo é gerido no Account Console!

---

## Tarefa 3: Configurar Service Principal para Automação CI/CD

1. No Account Console, acesse a aba 'Service Principals'.
2. Clique em 'Add Service Principal'.
3. Vincule a identidade gerenciada do Microsoft Entra ID criada para o Azure DevOps.
4. Conceda permissão de acesso ao workspace corporativo para permitir deploy automatizado via Databricks Asset Bundles (DABs).
