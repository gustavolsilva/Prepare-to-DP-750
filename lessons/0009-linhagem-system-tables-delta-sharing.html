🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Explore a observabilidade profunda do Unity Catalog: rastreamento de linhagem ponta a ponta (coluna e tabela), consultas SQL analíticas em System Tables e compartilhamento seguro via Delta Sharing. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: O Unity Catalog captura linhagem em tempo de execução sem custo adicional de instrumentação, cobrindo tabelas, colunas, notebooks, dashboards e pipelines DLT. As System Tables residem no catálogo especial `system` e incluem `system.access.audit` (logs de auditoria de quem leu ou modificou qualquer tabela), `system.billing.usage` (consumo de DBUs por cluster, SKU e tags de faturamento) e `system.lineage.table_lineage`. Para compartilhamento com terceiros, o Delta Sharing implementa um protocolo aberto REST que permite consultar dados em tempo real a partir do Power BI, Excel, Pandas ou Databricks externo sem cópia de arquivos.

Diretriz oficial DP-750 & Decisão Arquitetural: Questão garantida no DP-750: Como monitorar os custos de DBUs de um departamento específico no Azure Databricks? Criam-se tags de cluster obrigatórias via Cluster Policy (ex: `CostCenter = 'Finance'`), que são propagadas automaticamente para a tabela `system.billing.usage`. Uma simples consulta SQL agregando `usage_quantity` filtrando por `custom_tags['CostCenter']` gera relatórios precisos de chargeback. No Delta Sharing, os dados compartilham snapshots protegidos por tokens temporários do ADLS Gen2 com zero egress para destinatários na mesma região.

Mecânica Interna & Governança Executiva: Lakehouse Federation: O Unity Catalog permite criar Foreign Catalogs conectados a fontes externas (ex: Azure SQL Database, Snowflake, Google BigQuery). As queries SQL rodam com pushdown de predicados na fonte remota, permitindo joins federados entre um Delta Lake local no ADLS Gen2 e uma tabela de CRM legado no SQL Server com governança unificada. Em termos de FinOps corporativo: Monetização de Dados e Auditoria: Delta Sharing transforma o Lakehouse em um hub de troca de dados segura entre parceiros comerciais sem vendor lock-in, enquanto as System Tables garantem conformidade total com auditorias contábeis e de segurança.

Hands-on Lab Walkthrough

Lab 0009: Rastreamento de Linhagem e Auditoria Avançada com System Tables

⏱️ Tempo Estimado: 35 minutos
📖 Cenário do Laboratório:

Consultar tabelas de auditoria do sistema (system.access.audit e system.billing.usage) e inspecionar a linhagem automática de dados no Catalog Explorer.

Tarefa 1 Consultar Logs de Auditoria de Acessos

1. Abra o SQL Editor ou um notebook conectado ao SQL Warehouse. 2. Execute a consulta em `system.access.audit`:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
-- Consulta eventos de leitura e gravação no Unity Catalog
SELECT 
    event_time,
    user_identity.email,
    action_name,
    request_params.table_name,
    source_ip_address
FROM system.access.audit
WHERE service_name = 'unityCatalog'
  AND event_date >= current_date() - INTERVAL 7 DAYS
ORDER BY event_time DESC
LIMIT 15;
✓ Saída Esperada no Console Databricks: Exibe registros de auditoria com e-mail, ação (getTable, readTable), tabela acessada e IP de origem.

Tarefa 2 Analisar Consumo de DBUs para FinOps

1. Execute a agregação de faturamento em `system.billing.usage`:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
-- Relatório de consumo de DBUs por SKU e Data
SELECT 
    usage_date,
    sku_name,
    SUM(usage_quantity) AS total_dbus
FROM system.billing.usage
WHERE usage_date >= current_date() - INTERVAL 30 DAYS
GROUP BY 1, 2
ORDER BY usage_date DESC, total_dbus DESC;
✓ Saída Esperada no Console Databricks: Exibe tabela com consumo diário de DBUs segregado por SKU (STANDARD_ALL_PURPOSE, JOBS, SERVERLESS_SQL).
