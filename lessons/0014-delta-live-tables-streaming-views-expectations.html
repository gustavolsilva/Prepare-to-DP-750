🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Construa pipelines confiáveis com Delta Live Tables (Lakeflow): crie Streaming Tables, Materialized Views, garanta qualidade de dados com Expectations e aplique CDC com APPLY CHANGES INTO. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: Delta Live Tables (DLT) simplifica o desenvolvimento de ETL através de um framework puramente declarativo em SQL (`CREATE OR REFRESH STREAMING TABLE`) ou Python (`@dlt.table`). DLT gerencia automaticamente o grafo acíclico dirigido (DAG), orquestração de dependências, tratamento de erros e infraestrutura de cluster. As Data Quality Expectations garantem governança em três níveis: 1) `@dlt.expect('nome', 'condição')` (apenas registra no log de qualidade), 2) `@dlt.expect_or_drop('nome', 'condição')` (descarta a linha inválida e prossegue), e 3) `@dlt.expect_or_fail('nome', 'condição')` (aborta o pipeline imediatamente). Para ingestão de CDC (Change Data Capture), a instrução `dlt.apply_changes()` processa automaticamente upserts de chaves com SCD Tipo 1 ou Tipo 2.

Diretriz oficial DP-750 & Decisão Arquitetural: Questão recorrente no DP-750: Diferença crucial entre Streaming Tables e Materialized Views no DLT! Streaming Tables processam dados de fontes append-only de forma estritamente incremental e mantêm o histórico da tabela mesmo que os dados na fonte original sejam descartados. Materialized Views recalculam os resultados para refletir o estado mais recente dos dados da fonte (ideal para agregações complexas, joins e tabelas Gold de BI).

Mecânica Interna & Governança Executiva: O DLT grava todas as métricas de execução, qualidade de dados (linhas aprovadas, linhas descartadas) e linhagem em um Event Log em formato Delta Lake armazenado no storage do pipeline. Engenheiros podem consultar esse Event Log via SQL para criar dashboards operacionais de observabilidade corporativa. Em termos de FinOps corporativo: Confiabilidade de Dados (Data Reliability): O DLT transforma a engenharia de dados em um processo auditável com SLAs mensuráveis, eliminando custos de manutenção de scripts manuais de orquestração e garantindo que dados de baixa qualidade nunca alcancem relatórios de diretoria.

🌱 Lente Júnior: Fundamentos & Analogia do Mundo Real

Delta Live Tables (DLT) é como a fábrica automatizada da montadora de carros: em vez de você ligar cada máquina, transportar peças no carrinho de mão e conferir parafuso por parafuso manualmente, você apenas define a planta da fábrica (código declarativo). A linha de produção anda sozinha e descarta peças defeituosas automaticamente (Expectations)!

Lab 0014: Pipelines Declarativos com Delta Live Tables (DLT) e Expectations

⏱️ Tempo Estimado: 45 minutos
📖 Cenário do Laboratório:

Construir um pipeline corporativo DLT em Python declarativo com Streaming Tables, Materialized Views e regras de qualidade de dados (Expectations: EXPECT, DROP ROW, FAIL UPDATE).

Tarefa 1 Criar o Arquivo de Código Python do DLT

1. No Workspace, crie um notebook chamado `dlt_orders_pipeline` com linguagem Python. 2. Insira o código declarativo oficial do DLT:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
import dlt
from pyspark.sql.functions import col, expr

# 1. Camada Bronze: Streaming Table ingerindo dados contínuos
@dlt.table(
    name="bronze_pedidos_raw",
    comment="Tabela Bronze de pedidos brutos"
)
def bronze_pedidos_raw():
    return (spark.readStream
        .format("cloudFiles")
        .option("cloudFiles.format", "json")
        .load("/tmp/dlt_pedidos_in/"))

# 2. Camada Silver: Com Expectations de governança de qualidade
@dlt.table(
    name="silver_pedidos_validos",
    comment="Tabela Silver com regras de integridade"
)
@dlt.expect_or_drop("valor_positivo", "valor > 0")
@dlt.expect("cliente_obrigatorio", "cliente_id IS NOT NULL")
def silver_pedidos_validos():
    return dlt.read_stream("bronze_pedidos_raw").select("pedido_id", "cliente_id", "valor")

# 3. Camada Gold: Materialized View agregada para relatórios de BI
@dlt.table(
    name="gold_faturamento_cliente",
    comment="Visão materializada de faturamento"
)
def gold_faturamento_cliente():
    return (dlt.read("silver_pedidos_validos")
        .groupBy("cliente_id")
        .agg(expr("sum(valor) as total_gasto")))
