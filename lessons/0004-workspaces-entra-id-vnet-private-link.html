🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Aprenda a arquitetar workspaces corporativos com VNet Injection (duas subnets /26), provisionamento automático de identidades via SCIM e Microsoft Entra ID, e isolamento total via Azure Private Link. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: O provisionamento do Azure Databricks pode ocorrer no modo padrão (onde a Databricks cria uma VNet gerenciada dentro do Resource Group gerenciado) ou no modo VNet Injection (Customer-Managed VNet). A VNet Injection exige duas subnets delegadas exclusivas para `Microsoft.Databricks/workspaces`: a Public Subnet (host) e a Private Subnet (container), cada uma com máscara mínima de `/26` (64 IPs) para comportar a escala dos nós de computação. A sincronização de usuários, grupos e Service Principals do Microsoft Entra ID para o Unity Catalog é feita a nível de conta (Account Console) via conector SCIM.

Diretriz oficial DP-750 & Decisão Arquitetural: Cenário de Exame DP-750: Quando o tráfego de dados corporativos não pode navegar pela Internet pública sob nenhuma hipótese, deve-se implementar Azure Private Link. Existem dois tipos de conexões Private Link no Databricks: Front-end Private Link (conecta a rede local/usuário via ExpressRoute/VPN ao WebApp/Control Plane) e Back-end Private Link (conecta os nós do Compute Plane na VNet do cliente ao Control Plane e ao storage de infraestrutura). Service Principals configurados no Entra ID com OIDC são a melhor prática para automação de CI/CD sem expor senhas.

Mecânica Interna & Governança Executiva: Em arquiteturas com VNet Injection e Private Link, o Network Security Group (NSG) das subnets não pode bloquear a comunicação interna entre os nós do cluster na porta 443 e portas de shuffle (portas 43000-45000). O roteamento de saída para serviços Azure (ADLS Gen2, Azure Key Vault) deve ser configurado via Private Endpoints ou Service Endpoints nas subnets para evitar qualquer saída via NAT Gateway público. Em termos de FinOps corporativo: Centralização de Governança: Com o Unity Catalog no nível de conta, não se criam mais usuários manualmente em cada workspace individual. O conector SCIM sincroniza os grupos do Entra ID corporativo diretamente no Account Console da Databricks, garantindo conformidade com processos de onboarding e offboarding imediato de colaboradores.

Hands-on Lab Walkthrough

Lab 0004: Segurança de Rede (VNet Injection) e Sincronização Microsoft Entra ID (SCIM)

⏱️ Tempo Estimado: 40 minutos
📖 Cenário do Laboratório:

A equipe de segurança da informação exige que todo o ambiente Databricks opere dentro de uma VNet corporativa isolada com duas subnets dedicadas /26 e que os acessos sejam sincronizados automaticamente a partir do Microsoft Entra ID via conector SCIM.

Tarefa 1 Validar Requisitos de VNet Injection no Azure Portal

1. No portal do Azure, acesse 'Virtual Networks' e localize a VNet do Databricks. 2. Verifique as duas subnets obrigatórias: - Subnet 1 (Public/Host): Mínimo /26 (ex: 10.0.1.0/24), delegada para 'Microsoft.Databricks/workspaces'. - Subnet 2 (Private/Container): Mínimo /26 (ex: 10.0.2.0/24), delegada para 'Microsoft.Databricks/workspaces'. 3. Verifique o Network Security Group (NSG) associado para garantir que não haja regras de bloqueio de saída na porta 443 nem entre subnets para tráfego de shuffle interno.

Tarefa 2 Inspecionar o Databricks Account Console para Sincronização SCIM

1. Acesse o console corporativo do Databricks em `https://accounts.azuredatabricks.net`. 2. No menu lateral, clique em 'User Management'. 3. Observe a lista de usuários e grupos sincronizados a partir do Microsoft Entra ID. 4. Verifique a existência de grupos corporativos (ex: `dp750_data_engineers`, `dp750_bi_analysts`). No exame DP-750, a governança moderna proíbe a criação de usuários manuais em cada workspace individual; tudo é gerido no Account Console!

Tarefa 3 Configurar Service Principal para Automação CI/CD

1. No Account Console, acesse a aba 'Service Principals'. 2. Clique em 'Add Service Principal'. 3. Vincule a identidade gerenciada do Microsoft Entra ID criada para o Azure DevOps. 4. Conceda permissão de acesso ao workspace corporativo para permitir deploy automatizado via Databricks Asset Bundles (DABs).
