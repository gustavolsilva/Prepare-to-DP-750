🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Conecte com segurança seu lakehouse ao ecossistema Azure: Secret Scopes protegidos pelo Azure Key Vault, Managed Identities e External Locations com Storage Credentials do Unity Catalog. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: Para evitar vazamento de credenciais em notebooks ou repositórios Git, cria-se um Secret Scope backed por Azure Key Vault através da URL especial `https://#secrets/createScope`. No código PySpark/Python, o segredo é lido dinamicamente com `dbutils.secrets.get(scope='meu-scope', key='minha-chave')`, e o Databricks mascara automaticamente o valor retornado na saída do notebook como `[REDACTED]`. Para conexão com o ADLS Gen2 no Unity Catalog, a arquitetura moderna abandona montagens legadas (`dbutils.fs.mount`) e utiliza Storage Credentials associadas a Azure Managed Identity com permissão Storage Blob Data Contributor.

Diretriz oficial DP-750 & Decisão Arquitetural: Pegadinha crítica do DP-750: O uso de montagens `dbutils.fs.mount()` e chaves de acesso (Access Keys) em arquivos de configuração é considerado padrão LEGADO e inseguro. O exame exige Unity Catalog Storage Credentials e External Locations (`CREATE EXTERNAL LOCATION ... URL 'abfss://...' WITH (STORAGE CREDENTIAL ...)`). Dessa forma, o acesso aos arquivos não depende do usuário que rodou o cluster, mas sim do RBAC granular gerenciado centralmente no Metastore.

Mecânica Interna & Governança Executiva: Ao integrar com Azure Data Factory (ADF), utiliza-se o Databricks Linked Service autenticado via Managed Identity ou Service Principal associado a um Secret no Key Vault. Quando o ADF dispara uma Databricks Notebook Activity, ele pode injetar parâmetros dinâmicos via `baseParameters`, consumidos no notebook via Databricks Widgets (`dbutils.widgets.get('param_name')`). Em termos de FinOps corporativo: Segurança e Conformidade: A integração direta com o Azure Key Vault e Managed Identity garante que tokens nunca sejam compartilhados entre membros do time, viabilizando rotação de segredos em tempo real sem interrupção de pipelines produtivos.

Lab 0006: Integração Segura com Azure Key Vault e Storage Credentials ADLS Gen2

⏱️ Tempo Estimado: 35 minutos
📖 Cenário do Laboratório:

A equipe de arquitetura proibiu credenciais em texto plano. Você deve conectar o Databricks ao Azure Key Vault via Secret Scope e configurar Storage Credentials no Unity Catalog via Managed Identity para acessar o ADLS Gen2.

Tarefa 1 Obter os Dados do Azure Key Vault

1. No Azure Portal, abra o recurso Azure Key Vault. 2. Na aba 'Properties', copie: - DNS Name (ex: `https://kv-dp750-prod.vault.azure.net/`) - Resource ID (ex: `/subscriptions/.../resourceGroups/.../providers/Microsoft.KeyVault/vaults/...`) 3. Na aba 'Secrets', crie um segredo chamado `adls-access-token` com um valor de teste.

Tarefa 2 Criar o Secret Scope Backed pelo Azure Key Vault no Databricks

1. No navegador, acerte a URL do seu workspace Databricks adicionando `#secrets/createScope` ao final: `https://#secrets/createScope` 2. Preencha os campos: - Scope Name: `kv-dp750-scope` - Manage Principal: Creator - DNS Name: cole o DNS Name do Key Vault - Resource ID: cole o Resource ID do Key Vault 3. Clique em 'Create'.

Tarefa 3 Recuperar o Segredo Mascarado via PySpark

1. Abra um notebook e execute o código de leitura do segredo:

Código para colar na célula do Notebook Databricks:
