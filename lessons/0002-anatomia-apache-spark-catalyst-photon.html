🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Compreenda a distribuição física do Apache Spark (Driver, Executors, Jobs, Stages, Tasks), a dinâmica de Shuffle e a revolução da engine Photon C++ integrada ao Catalyst Optimizer. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: Um programa Spark submete Ações (como .count(), .write(), .collect()) que disparam Jobs. Cada Job é fragmentado em Stages divididos por limites de Shuffle (operações de Wide Transformation como groupBy, join, distinct). Os Stages são quebrados em Tasks, que representam a unidade elementar de execução processando uma partição de dados em um Core/Slot de Executor. O Catalyst Optimizer atua compilando a query em 4 fases: Resolved Logical Plan, Analyzed Logical Plan, Optimized Logical Plan (com Predicate Pushdown e Column Pruning) e Physical Plan com geração de código Java bytecode (Tungsten).

Diretriz oficial DP-750 & Decisão Arquitetural: No exame DP-750, a chave para performance é evitar Shuffles desnecessários (troca massiva de dados pela rede entre executors). O Photon Engine é o motor de execução nativo da Databricks reescrito do zero em C++, que substitui o Tungsten. Ele opera execução vetorizada (SIMD) processando milhares de linhas por instrução de CPU em memória colunar, acelerando agregações, joins e scans em até 3x a 8x em relação ao Spark tradicional.

Mecânica Interna & Governança Executiva: O Photon trabalha diretamente no nível da instrução de máquina, eliminando a sobrecarga de Garbage Collection (GC) da JVM e otimizando o branch prediction da CPU. Quando o Catalyst gera o Physical Plan, ele substitui os operadores WholeStageCodegen convencionais por nós Photon (ex: PhotonFilter, PhotonHashAggregate, PhotonShuffleExchangeExec), garantindo fallback transparente para JVM caso uma função não suportada (como uma UDF Python não vetorizada) seja encontrada. Em termos de FinOps corporativo: Embora clusters habilitados com Photon possuam um multiplicador ligeiramente maior na cobrança de DBUs, o ganho de velocidade (redução do tempo de pipeline pela metade ou um terço) resulta em um custo total final menor (menor tempo de VM Azure + menor tempo de cluster ativo).

🌱 Lente Júnior: Fundamentos & Analogia do Mundo Real

O Driver do Spark é como o maestro de uma grande orquestra: ele não toca todos os instrumentos sozinho, mas divide a partitura completa em pequenas estrofes (Tasks) e distribui para os músicos (Executors). Cada executor toca sua parte em paralelo, e o resultado final é uma sinfonia executada em segundos!

Lab 0002: Análise de Planos de Execução do Catalyst e Photon Engine

⏱️ Tempo Estimado: 35 minutos
📖 Cenário do Laboratório:

Investigar a fundo os 4 estágios de otimização de consultas do Apache Spark (Resolved Logical, Analyzed, Optimized e Physical Plan) e comparar o ganho de throughput de scans e agregações com o Photon Vectorized Engine em C++.

Tarefa 1 Criar Cluster com Aceleração Photon Habilitada

1. No Databricks Workspace, navegue em 'Compute' > 'Create compute'. 2. Habilite a caixa de seleção 'Use Photon Acceleration'. 3. Selecione o runtime '15.4 LTS (Photon)' e configure autotermination para 20 minutos. 4. Inicie o cluster 'dp750-photon-cluster'.

Tarefa 2 Gerar Massa de Dados Sintética e Inspecionar o Plano Catalyst

1. Crie o notebook 'lab_0002_catalyst_photon' e anexe-o ao cluster Photon. 2. Execute o código PySpark abaixo para inspecionar os planos lógico e físico:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
from pyspark.sql.functions import col, expr, rand

# Gera um DataFrame distribuído de 5 milhões de linhas para teste de stress
df = spark.range(0, 5000000).withColumn("categoria", expr("CASE WHEN id % 4 = 0 THEN 'TECH' WHEN id % 4 = 1 THEN 'FIN' WHEN id % 4 = 2 THEN 'HEALTH' ELSE 'EDU' END")) \
                           .withColumn("valor", rand() * 1000)

# Consulta com agregação e filtro (Wide Transformation)
df_analise = df.filter(col("valor") > 250) \
               .groupBy("categoria") \
               .agg(expr("sum(valor) as total_vendas"), expr("count(*) as transacoes"))

# Inspeciona os 4 estágios do Catalyst Optimizer:
print("=" * 70)
print("PLANO DETALHADO DO CATALYST OPTIMIZER:")
print("=" * 70)
df_analise.explain(extended=True)
