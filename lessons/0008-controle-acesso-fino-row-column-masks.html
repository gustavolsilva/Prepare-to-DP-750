🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Implemente segurança de nível militar: privilégios hierárquicos (GRANT/REVOKE), mascaramento dinâmico de PII com Column Masks e restrição territorial de linhas com Row Filters SQL. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: O Unity Catalog opera um modelo de herança de privilégios estrito: para consultar uma tabela, o usuário precisa de `USE CATALOG` no catálogo pai, `USE SCHEMA` no schema pai e `SELECT` na tabela. Row Filters e Column Masks são definidos através de SQL User-Defined Functions (UDFs). Um Row Filter retorna um valor booleano (`true`/`false`) avaliando a função de contexto `is_account_group_member('grupo')` ou `current_user()`. Uma Column Mask recebe o valor original da coluna e retorna uma versão mascarada caso o usuário não pertença ao grupo privilegiado.

Diretriz oficial DP-750 & Decisão Arquitetural: Tema quente no DP-750: Como associar uma máscara a uma tabela existente? Utiliza-se `ALTER TABLE tbl ALTER COLUMN cpf SET MASK mask_cpf_func;` ou durante a criação com `CREATE TABLE`. Para Row Filters: `ALTER TABLE tbl SET ROW FILTER filter_region_func ON (region);`. A grande vantagem sobre as antigas Dynamic Views é que Row Filters e Column Masks funcionam de forma transparente: analistas consultam diretamente a tabela base `catalog.schema.table` sem necessidade de criar e manter centenas de views intermediárias.

Mecânica Interna & Governança Executiva: Performance e Otimização do Catalyst com Row Filters: O otimizador de consultas do Spark incorpora as regras do Row Filter diretamente no Logical Plan durante a fase de Analysis. Se o usuário só tem permissão para a região 'BR', o Catalyst aplica Predicate Pushdown imediato no scan dos arquivos Delta/Parquet, descartando arquivos de outras regiões no nível de metadados sem sobrecarga de I/O. Em termos de FinOps corporativo: Compliance LGPD/GDPR: A capacidade de mascarar CPF, salários e dados médicos a nível de storage com herança automática simplifica auditorias e garante que desenvolvedores em homologação nunca visualizem dados pessoais de clientes.

Lab 0008: Controle de Acesso Fino: Row Filters e Column Masks no Unity Catalog

⏱️ Tempo Estimado: 35 minutos
📖 Cenário do Laboratório:

Configurar segurança granular em uma tabela corporativa para que analistas vejam apenas registros de sua própria região e tenham dados de PII (CPF) mascarados dinamicamente.

Tarefa 1 Criar Tabela com Dados Pessoais Sensíveis

1. Abra um notebook e execute o script de criação da tabela de clientes:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
CREATE SCHEMA IF NOT EXISTS dp750_corp_catalog.seguranca;

CREATE OR REPLACE TABLE dp750_corp_catalog.seguranca.clientes_sensivel (
    id INT,
    nome STRING,
    regiao STRING,
    cpf STRING,
    salario DOUBLE
);

INSERT INTO dp750_corp_catalog.seguranca.clientes_sensivel VALUES
(1, 'Carlos Silva', 'SUL', '12345678901', 8500.0),
(2, 'Mariana Costa', 'SUDESTE', '98765432100', 12000.0),
(3, 'Renato Santos', 'SUL', '55544433322', 6200.0);
✓ Saída Esperada no Console Databricks: ✓ Tabela criada e populada com 3 registros.

Tarefa 2 Definir e Aplicar Funções SQL de Row Filter e Column Masking

1. Crie as SQL UDFs de mascaramento e restrição de linha:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
-- 1. Criação do Row Filter por região geográfica
CREATE OR REPLACE FUNCTION dp750_corp_catalog.seguranca.filtro_regiao(regiao STRING)
RETURN IF(is_account_group_member('diretoria_global'), true, regiao = 'SUL');

-- 2. Aplica o Row Filter na tabela
ALTER TABLE dp750_corp_catalog.seguranca.clientes_sensivel 
SET ROW FILTER dp750_corp_catalog.seguranca.filtro_regiao ON (regiao);

-- 3. Criação da Column Mask para mascarar CPF
CREATE OR REPLACE FUNCTION dp750_corp_catalog.seguranca.mascara_cpf(cpf STRING)
RETURN IF(is_account_group_member('rh_auditoria'), cpf, CONCAT('***.***.', RIGHT(cpf, 3)));

-- 4. Aplica a Column Mask na coluna CPF
ALTER TABLE dp750_corp_catalog.seguranca.clientes_sensivel 
ALTER COLUMN cpf SET MASK dp750_corp_catalog.seguranca.mascara_cpf;

-- 5. Consulta de teste
SELECT * FROM dp750_corp_catalog.seguranca.clientes_sensivel;
✓ Saída Esperada no Console Databricks: +---+------------+------+-----------+-------+

| 1|Carlos Silva| SUL|***.***.901| 8500.0|
| 3|Renato Santos| SUL|***.***.322| 6200.0|
