🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Construa pipelines com a Arquitetura Medallion (Bronze, Silver, Gold), manipule dados complexos com PySpark/Spark SQL e implemente Slowly Changing Dimensions (SCD Tipo 1 e 2) com MERGE INTO. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: A Camada Bronze armazena dados brutos preservando histórico (append-only) com metadados de ingestão (`input_file_name()`, `current_timestamp()`). A Camada Silver limpa, deduplica, tipa e normaliza as entidades através de operações de enriquecimento e MERGE. A Camada Gold consolida modelos analíticos prontos para consumo de BI em formato dimensional (fatos e dimensões agregadas). Para manutenção de dimensões de clientes, o comando `MERGE INTO target USING source ON target.id = source.id` permite aplicar SCD Tipo 1 (sobrescrevendo atributos mutáveis) ou SCD Tipo 2 (mantendo histórico através de linhas com `is_current = false` e data de encerramento de vigência).

Diretriz oficial DP-750 & Decisão Arquitetural: Ponto de ouro do exame DP-750: Otimização de comandos MERGE INTO no Delta Lake. Quando a tabela de destino for particionada ou clusterizada, a cláusula ON do MERGE DEVE incluir a coluna de partição ou chave de clustering (`AND target.date = source.date`). Isso permite Partition Pruning e File Pruning, impedindo que o Spark faça Full Table Scan em terabytes de dados históricos para atualizar apenas um lote do dia.

Mecânica Interna & Governança Executiva: Internals do MERGE: O Delta Lake executa o merge em duas fases: um Inner Join inicial para identificar quais arquivos contêm registros correspondentes (target matching), seguido de uma fase de reescrita onde apenas os arquivos afetados são atualizados e gravados como novos Parquets (ou marcados via Deletion Vectors caso habilitados, reduzindo o I/O em até 80%). Em termos de FinOps corporativo: Alinhamento Estratégico: A separação clara das camadas Medallion permite segregação de custos e acessos: apenas engenheiros têm acesso à camada Bronze; analistas de negócio consomem exclusivamente a camada Gold com respostas em subsegundos e dados 100% auditados.

Lab 0011: Construção de Pipeline Medallion e Upserts MERGE (SCD1 e SCD2)

⏱️ Tempo Estimado: 45 minutos
📖 Cenário do Laboratório:

Construir a esteira completa Medallion (Bronze -> Silver -> Gold) com deduplicação por Window Functions e operações de MERGE INTO para SCD Tipo 1 e Tipo 2.

Tarefa 1 Construir Camada Bronze e Limpeza Silver com Deduplicação

1. No notebook 'lab_0011_medallion', execute a deduplicação com funções de janela:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
from pyspark.sql.window import Window
from pyspark.sql.functions import col, row_number

# Dados simulados com duplicidade e timestamps distintos
raw_data = [
    (101, "Lucas Mendes", "Curitiba", "2025-01-01 10:00:00"),
    (101, "Lucas Mendes", "São Paulo", "2025-01-02 15:30:00"), # Mais recente
    (102, "Carla Dias", "Belo Horizonte", "2025-01-01 11:00:00")
]
df_raw = spark.createDataFrame(raw_data, ["cliente_id", "nome", "cidade", "data_modificacao"])

# Deduplica selecionando apenas a linha mais recente por cliente_id
window_spec = Window.partitionBy("cliente_id").orderBy(col("data_modificacao").desc())
df_silver = df_raw.withColumn("rn", row_number().over(window_spec)).filter(col("rn") == 1).drop("rn")

df_silver.write.format("delta").mode("overwrite").saveAsTable("default.silver_clientes")
print("✓ Camada Silver deduplicada com sucesso!")
spark.sql("SELECT * FROM default.silver_clientes").show()

Tarefa 2 Executar MERGE INTO para SCD Tipo 2 (Histórico Vigencial)

1. Na Célula 2, execute o padrão ouro de SCD2 no Delta Lake:

Código para colar na célula do Notebook Databricks: 
# COMMAND ----------
-- Criação da tabela de dimensão Gold com colunas de controle temporal
CREATE OR REPLACE TABLE default.gold_dim_clientes (
    cliente_id INT,
    nome STRING,
    cidade STRING,
    start_date DATE,
    end_date DATE,
    is_current BOOLEAN
);

-- Carga inicial
INSERT INTO default.gold_dim_clientes VALUES
(101, 'Lucas Mendes', 'São Paulo', '2025-01-01', NULL, true);

-- Chegada de nova atualização (mudou para Salvador):
-- 1. Expira registro antigo
MERGE INTO default.gold_dim_clientes AS target
USING (SELECT 101 AS cliente_id, 'Salvador' AS nova_cidade) AS source
ON target.cliente_id = source.cliente_id AND target.is_current = true
WHEN MATCHED AND target.cidade <> source.nova_cidade THEN
  UPDATE SET target.is_current = false, target.end_date = current_date();

-- 2. Insere novo registro vigente
INSERT INTO default.gold_dim_clientes VALUES
(101, 'Lucas Mendes', 'Salvador', current_date(), NULL, true);

SELECT * FROM default.gold_dim_clientes;
