🌐 Visão Unificada Completa: Integração Arquitetural de Ponta a Ponta

Eleve seus pipelines a nível empresarial: orquestre tarefas com Databricks Workflows (DAGs, Task Values, Repair Run), implemente CI/CD com Databricks Asset Bundles (DABs) e monitore via Spark UI e Azure Monitor. Esta lição articula a ponte entre os fundamentos conceituais, a prática de engenharia no Azure Databricks e os critérios rigorosos de aprovação no exame Microsoft DP-750.

No dia a dia prático: Databricks Workflows é o orquestrador nativo totalmente gerenciado do Lakehouse. Ele permite criar Jobs compostos por múltiplas tarefas (Notebooks, Python Scripts, DLT Pipelines, SQL Queries, dbt) organizadas em um DAG com dependências condicionais (`Run if: All succeeded`, `At least one succeeded`). Variáveis dinâmicas são passadas entre tarefas downstream através de Task Values (`dbutils.jobs.taskValues.set()` e `.get()`). Em caso de falha de uma tarefa em um job com 10 etapas, a funcionalidade **Repair Run** reexecuta apenas a tarefa com falha e suas dependências, poupando tempo e custo de computação.

Diretriz oficial DP-750 & Decisão Arquitetural: Tema central obrigatório do DP-750: **Databricks Asset Bundles (DABs)** é a abordagem moderna padrão de Infrastructure as Code (IaC) e CI/CD para Databricks. O arquivo `databricks.yml` declara pipelines, jobs, permissões e ambientes (`dev`, `staging`, `prod`). Com comandos CLI simples (`databricks bundle validate`, `databricks bundle deploy -t prod`, `databricks bundle run`), integra-se o desenvolvimento diretamente ao Azure DevOps Pipelines ou GitHub Actions sem configurações manuais no portal.

Mecânica Interna & Governança Executiva: Depuração avançada com Spark UI: Ao investigar gargalos em jobs de produção, o engenheiro de dados deve analisar as abas **Jobs**, **Stages** e **Executors**. A presença de **Spill (Memory)** e **Spill (Disk)** indica que partições de dados excederam a memória do executor e foram despejadas em disco, apontando para necessidade de repartitioning ou aumento de nós de worker. **Data Skew** é visualizado quando uma única task demora 10x mais que as outras no percentil 75/max da Stage UI. Em termos de FinOps corporativo: Maturidade de Engenharia de Dados: O uso de Databricks Asset Bundles (DABs) garante versionamento rigoroso, deploy automatizado sem intervenção humana e testes automatizados antes da ida a produção, reduzindo o tempo de lançamento de novos produtos de dados de meses para dias.

🌱 Lente Júnior: Fundamentos & Analogia do Mundo Real

Databricks Workflows é como o relógio despertador e a agenda do seu celular juntos: ele sabe que às 06:00 da manhã precisa tocar o despertador (Tarefa 1), depois ligar a cafeteira (Tarefa 2) e só depois te avisar que o café está pronto (Tarefa 3). Se faltar luz na cafeteira, ele te avisa e permite tentar de novo só a parte do café sem ter que voltar a dormir e acordar de novo (Repair Run)!

Hands-on Lab Walkthrough

Lab 0015: Orquestração em Produção: Databricks Workflows, DABs e Spark UI

⏱️ Tempo Estimado: 45 minutos
📖 Cenário do Laboratório:

Orquestrar um pipeline multitarefa no Databricks Workflows, utilizar Task Values, simular falha e executar Repair Run, além de validar o manifesto de Databricks Asset Bundles (databricks.yml).

Tarefa 1 Criar um Job Multitarefa no Databricks Workflows

1. No menu esquerdo, clique em 'Workflows' > 'Jobs' > 'Create job'. 2. Configure a Tarefa 1: - Task name: `01_bronze_ingestion` - Type: Notebook - Compute: New Job Cluster (Standard_D4ds_v5) 3. Clique no botão '+' abaixo da Tarefa 1 para adicionar a Tarefa 2: - Task name: `02_silver_transform` - Depends on: `01_bronze_ingestion` 4. Salve o Job com o nome `DP750-Production-Orchestrator`.

Tarefa 2 Utilizar Task Values para Passagem de Parâmetros

1. Na Tarefa 1, insira o código PySpark para exportar o ID do lote: `dbutils.jobs.taskValues.set(key="batch_run_id", value="LOTE_2025_001")` 2. Na Tarefa 2, insira o código para consumir o valor: `lote = dbutils.jobs.taskValues.get(taskKey="01_bronze_ingestion", key="batch_run_id")` `print(f'Processando lote: {lote}')`

Tarefa 3 Simular Falha e Executar o Recurso 'Repair Run'

1. Adicione um comando proposital de erro na Tarefa 2 (`raise ValueError('Erro temporário de conexão')`). 2. Clique em 'Run now'. O job executará a Tarefa 1 com sucesso e falhará na Tarefa 2. 3. Corrija o erro no notebook da Tarefa 2. 4. Na tela de execução do Job, clique no botão 'Repair run'. Observe que a Tarefa 1 NÃO É REEXECUTADA, poupando tempo e DBUs, executando exclusivamente a Tarefa 2 que havia falhado!

Tarefa 4 Validar Manifesto de Databricks Asset Bundles (databricks.yml)

1. Em seu terminal local, crie o arquivo `databricks.yml` e valide a sintaxe oficial: `databricks bundle validate` 2. Observe a saída confirmando que os recursos de jobs e pipelines estão sintaticamente corretos para deploy via CI/CD no Azure DevOps ou GitHub Actions.
